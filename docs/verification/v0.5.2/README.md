## 问题

用户会话（`session-b784ba0b…`）里，预览最后几张图总是裂的、翻页页也打不开。

复现后确认：裂的是 **Markdown 里用相对路径引用的图片**（如 `.artifacts/usage-source-chip-v2/images/01-现状问题.png`）。v0.5.0/0.5.1 的会话索引直接把原始相对路径当 URL 拼到页面 origin 上：

```
http://127.0.0.1:3099/.artifacts/.../01-现状问题.png  → 404
```

而 DSH 的 Markdown 渲染器会把这类文件引用解析成 `/api/file?...` 的文件地址；插件索引没有用到这个解析结果，于是缩略图和预览页都裂。附件图不受影响。

## 修复

- 相对/绝对本地文件路径的 Markdown 引用先标记为未解析；
- 打开预览时扫描页面上**已渲染的 Markdown 图片**，按文件名（兼容 URL 编码）或 alt 把未解析条目映射到浏览器真实 `src`（`/api/file?...`、blob 等）；
- 仍未渲染、无法解析的图片**不进入翻页索引**（避免裂图占页），用户仍可直接点开该图；
- 缩略图加载失败时显示中性占位符，不再显示破图图标。
